BT Group: uma malha de eventos para toda a nuvem híbrida de uma telecom

Como a operadora britânica construiu um backbone de streaming governado entre on-premises, AWS, GCP e SaaS.

{{ cover }}

Contexto

O BT Group é uma das maiores empresas de telecomunicações do Reino Unido. Dentro da unidade de arquitetura, o time de integração é responsável por plataformas de APIs, microsserviços, ETL, transferência de arquivos e streaming de eventos para toda a empresa.

O problema

Em 2020, a arquitetura de integração da unidade digital não tinha uma capacidade de streaming de eventos em larga escala. Muitos requisitos internos exigiam processamento de eventos com baixa latência, e as aplicações estavam espalhadas entre on-premises, AWS (usada para modernização de aplicações), Google Cloud (escolhida para BI, analytics e IA) e serviços SaaS de terceiros.

A solução

O time recebeu uma missão clara: desenhar e entregar um backbone de streaming conectado para toda a nuvem híbrida do grupo. O resultado é a Smart Event Mesh, com streaming centralizado e consumo descentralizado, construída sobre Confluent. Kafka Connect e ksqlDB foram adotados para transformar e mover dados em tempo quase real entre os ambientes.

Resultados

A Confluent descreve fluxos de dados em tempo real bem governados disponíveis em todo o ambiente de nuvem híbrida do BT, com eventos que podem ser descobertos e consumidos em autosserviço pelos times. O caso não publica números de volume ou economia.

O que isso diz para quem opera no Brasil

Quase todo cliente grande que atendemos tem o mesmo desenho do BT: parte no data center, parte em uma nuvem para aplicações e outra nuvem para dados e IA. Sem um backbone de eventos comum, cada integração vira um projeto. A malha de eventos com contratos de schema e governança central é o que permite aos times consumirem dados sem pedir ao time de integração a cada vez.
