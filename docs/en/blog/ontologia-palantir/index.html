The Ontology as the business semantic layer, explained for data warehouse people

Objects, properties, links and actions: what changes compared with tables and dashboards, and why it matters for AI.

{{ cover }}

From star schema to business object

In a data warehouse, the business is represented in fact and dimension tables designed for querying. Whoever uses the data must know how tables join to answer a question. Palantir’s Ontology starts somewhere else: it represents the business as objects people recognize, such as customer, order, machine or patient.

The four elements

Object types define business entities. Properties describe each object, such as status, value or location. Links connect objects, for example an order to a customer and a plant. Actions define what can be done to objects, with rules and permissions, such as approving, reallocating or opening a work order.

Behind every object there are still datasets and pipelines. The difference is that users do not need to know them.

What changes in practice

Applications, analyses and automations are built on the same model. A change made through an action, such as raising an order’s priority, is recorded on the object and visible to everyone who depends on it. That closes the loop between analyzing and acting, which in a data warehouse usually happens outside the system, by email or spreadsheet.

Why it matters for AI

A language model does not know what a late order means in your company. The Ontology gives it that context: which objects exist, how they relate and which actions are allowed. That is why AIP uses the Ontology as the foundation for agents and AI workflows.

Answer quality depends on the object being current. An Ontology fed by real-time events delivers context from now; one fed by nightly loads delivers context from yesterday.

Where to start

Pick a process with a clear, recurring decision. Model only the objects and links that decision needs, define one or two actions and connect the sources. Expand from there, object by object, instead of trying to model the whole company at once.
